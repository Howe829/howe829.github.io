# 落子 · 与 Jev 对弈

15×15 自由五子棋，黑先白后，五子或以上获胜，不设禁手。访客自带 TypeSafe API Key。每颗白棋均来自真实 Jev Choice 调用，错误暂停，支持重试、悔棋、重新开始。密钥不持久化。

## 本地运行

Node.js 22+：`node dev-server.mjs`，访问 http://127.0.0.1:8790 。

测试：`node --test game.test.mjs`。

## Jev 如何下棋

程序根据现有棋子附近两格内的空位生成候选，计算连续线及两端空位等攻防提示，保留最多 24 个候选。Jev Choice 结合完整棋盘及候选提示选出落点。所有棋规、棋谱回放与终局检查由代码执行，前后端均校验。

这不是专业五子棋搜索引擎；候选筛选会限制 Jev 的可选范围，置信度不是胜率。每手最多一次 Jev 请求，失败重试可能再产生费用。程序不会在失败时冒充 Jev 代下。

## 战术上下文增强

每个候选附带白落子后的黑方立即赢点、白方反胜点及黑方制造两个不同赢点的应手。检查白方是否能先一步反胜，避免把可反击的威胁误判为必败。枚举所有五格窗口，覆盖断四；范围限于这些确定战术，不是完整搜索，也不保证棋力。

截图棋谱 H8/G8/G7/H7/F6 的第六手：I6 明确允许黑 I9 后 E5/J10 双赢点；E5 与 I9 不留下该必败路线。第八手已有活四时所有候选均标明黑方下一手可赢。14 项测试通过；尚未用真实 Jev 验证增强上下文后的选择。

## 纯 Jev 连续威胁增强

每个候选增加有预算限制的连续冲四证明：最多三次进攻加最终赢点，逐步附带强制挡点；预算耗尽标记 UNKNOWN，不声称安全。黑方先行和反胜检查优先。保持全部原候选，不替换 Jev 的选择、不增加额外模型调用。17 项功能测试通过，包含双方颜色及旋转局面的独立赢点复核、反胜、预算耗尽和模型选择不被覆盖。真实模型胜率未验证，不宣称专业或无敌棋力。
